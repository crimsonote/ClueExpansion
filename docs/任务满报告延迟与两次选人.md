# 一、任务满报告延迟（`ClueMissionReportDelay`）

## 1.1 原版链路

任务满时（0.1.18 `MissionManager`）：

1. `ClearMission` 把任务进度 / 时间加上，然后 `CheckAllClear` 把
   `MissionManager.AllClear`（:169168）置 `true`。
2. `CheckAllClear` 调 `TriggerAllClearEnd()`（:169787，private）：
   - 有未发现尸体 → `Corpse.DiscoverByTimeOver()`（:171977），进调查；
   - 没有尸体 → `GameRoom.PushAfter(3000, ClearAllMission)`，白方胜利。
3. `AllClear == true` 时，`GameRoom.SurvivalTick()`（:174298）**直接 return 且不再重排**
   （:174300-174303）⇒ 熔毁倒计时天然停住；尸体的 survival job 也不再推进。

因此 **`TriggerAllClearEnd` 是唯一收口**：拦它一次，就同时阻止了“报告尸体”和“白方胜利”。

## 1.2 我们的规则

只处理“任务满”的那一次 `TriggerAllClearEnd`：

| 条件 | 行为 |
| --- | --- |
| 当前没有未发现尸体 | 放行原版 → 3 秒后白方胜利 |
| 有尸体，但 `StateList[5] - SurviveTime < ThresholdSeconds` | 放行原版 → 立即报告 |
| 有尸体，且剩余 `>= ThresholdSeconds` | 拦下；`PushAfter(DelaySeconds)` 后重入原版 |
| 手动报告 / 其它路径已进入非 `Survive` 阶段 | 一律不介入，放行/跳过由原版状态决定 |

`StateList[5]` 是尸体自动报告的 `SurviveTime` 目标（死亡时 `SurviveTime + WaitDetectiveSecond`，
`WaitDetectiveSecond` 为 50–70 秒）。用 **最老未发现尸体**（`FindOldestUndiscoveredCorpse`，
:174404）计算剩余，因为原版优先报告的就是它。

推迟期间：

- `TimeManager.RemainTime`（:181670）冻结：`UpdateRemainTime`（:181703）与
  `TickSurvive`（:181688）的 Postfix 把它压回冻结值，并在被改动时广播
  `S_UPDATE_REMAIN_TIME` 纠正客户端。
- `SurviveTime` 不推进（`SurvivalTick` 已停），尸体的自动报告 job 不推进。
- 到点后解冻，重入原版 `TriggerAllClearEnd`：尸体仍在就报告，尸体没了就按原版白胜。

## 1.3 配置

段 `[ClueMissionReportDelay]`：

| 键 | 默认 | 范围 | 含义 |
| --- | --- | --- | --- |
| `DelaySeconds` | 5 | 1–30 | 报告 + 白方结算推迟多少秒 |
| `ThresholdSeconds` | 40 | 0–120 | 尸体自动报告剩余 ≥ 该值才推迟 |

两个值都热读；`DelaySeconds <= 0` 视为不推迟。

## 1.4 边界与失败路径

- **手动报告**：手动报告不经过 `TriggerAllClearEnd`，不受影响。若在推迟中手动报告，
  `ChangeGameState` 的 Postfix 会 `Reset` 并 `Kill` 推迟 job；到点也不会再补发。
- **推迟中状态变化**：任何 `ChangeGameState` 都清状态；`ResetSurvival` / `FullReset` 同样清。
- **热关闭**：`OnDisabled` 若发现仍在推迟，立即 `Reset(true)` → 反射调用原版
  `TriggerAllClearEnd`，避免 `AllClear` 让 `SurvivalTick` 停摆导致整局卡死。
- **job 竞态**：如果关闭开关时 job 先到，`Retrigger` 发现功能已关也会走 `Reset(true)` 补原版；
  两条路径都幂等，不会双发。
- **迁移**：`Retrigger` 遇 `IsMigrating` 先顺延（保留冻结）；`ResumeAllClearAfterMigration`
  再调 `TriggerAllClearEnd` 时，如果 `_pending` 仍有效会继续拦下，不会绕过延迟。
  超过 watchdog（`DelaySeconds + 2s`，迁移额外 15s）则放行原版。
- **watchdog**：`TriggerAllClearEnd` 若在 `_pending` 超过 deadline 后才被调用，会先
  `Reset(false)` 再放行原版，不会永远拦着。
- **异常**：`Retrigger` / `InvokeOriginal` 都有 try/catch；反射目标缺失时退化为
  “直接报告最老尸体”，并在日志里明确报错。

# 二、两次选人（`CluePickSkill`）

## 2.1 目标口径

1. **模型阶段完全走原版**：40 秒、随机 `-2` 在 40 秒揭晓、强制分配都不改。
2. **两阶段完全独立**：模型只决定外观；进入技能阶段时，服务端释放所有人的模型默认技能，
   **所有技能重新变成无主**，再让所有人对全部技能先到先得。
3. **全局同步**：所有选人状态包一律 `GameRoom.Broadcast`，不存在“只对某个客户端成立”的
   伪造状态。
4. **完全重置选人界面**：进入技能阶段时清空所有头像、复位所有人的提交状态、点亮所有模型角色。
5. **匿名**：技能阶段选中的技能用 `S_PICK_CHARACTER { PlayerId = 0 }` 广播；
   别人只知道“该技能被占了”，不知道是谁选的。
6. **保留默认技能**：想保留自己的模型技能，就在第二次选自己的模型；如果该技能已被别人先选走，
   界面里它已经灰了，点不到；即使强行提交，服务端也按“已占用 → 随机”兜底。

## 2.2 阶段推进

### 模型阶段

- `PickCharacter`（:174189）完全放行原版；Postfix 只记录成功选中的模型
  （`_pickPlayers` / `_pickCharacters` 反射读取）。
- 压住 `CheckPickAllDone`（:174241），否则最后一个人选完模型就会把 `StopWatch` 置 40，
  技能阶段没有时间。
- **提前进入技能阶段**：当所有 `Players` 都有具体模型、且 `_randomPickPlayers` 为空时，
  直接进入技能阶段（不必等满 40 秒）。
- 否则等原版 40 秒那一拍：`PickCharacterTick`（:174091）先广播 `S_TIME{Time=0}`，
  再强制分配没选的人。我们在 `Broadcast` 的 Prefix 里**只拦这一条 0**，
  让客户端不执行 `SetTime(0)`（一旦执行，`_pickClosed=true`，按钮永久隐藏）；
  原版继续完成强制分配，Postfix 再进入技能阶段。

### 进入技能阶段（`StartSkillPhase`）

按顺序：

1. `EnsureModelsRecorded`：把原版 40 秒强制分配 / 随机揭晓的模型补进 `Model`。
2. 对 `Players` 里每个人 `SkillComponent.DeallocateSkill()`：撤销模型阶段的默认技能。
   ⚠️ 只改服务端真值，不发包；客户端 HUD 可能还显示旧技能，直到本人选定后
   `AllocateSkill` 发 `ChangeSkill`。选人阶段没有战斗，不影响玩法。
3. **完全重置选人界面**：对每个已选模型的玩家广播
   `S_CANCEL_PICK_CHARACTER { PlayerId = 该玩家, CharacterId = 模型 }`。
   每个客户端收到同一序列：
   - 所有玩家头像清空；
   - 所有模型角色重新点亮（`UI_PickSubItem.RefreshUI`）；
   - 每个客户端在自己的那条包上把 `_submit` 复位为 `false`，`_currentPick = -1`，
     随机按钮恢复。
4. `SetStopWatch(40 - SkillPickSeconds)`，广播 `S_TIME{Time = SkillPickSeconds}`。
   之后原版 `PickCharacterTick` 每秒的 `S_TIME{40 - StopWatch}` 正好与新的技能倒计时一致，
   到 40 时广播 `Time=0` 隐藏按钮，45 秒切换阶段。

### 技能阶段选择

参与者提交 `C_PICK_CHARACTER`：

| 情况 | 行为 |
| --- | --- |
| `CharacterId == -2` 且 `AllowRandom` | 从剩余技能随机 |
| `CharacterId == -2` 且 `AllowRandom == false` | 忽略，保持未提交，可继续手选 |
| 角色不存在 / `Madeline` / 技能已被占用 | 按“无法选择”处理：从剩余技能随机 |
| 正常且技能空闲 | 装上该角色对应的技能 |

一次成功选择：

1. `SkillComponent.DeallocateSkill()`（通常 Data 已为空）→ `AllocateSkill(角色)`；
   记录 `SkillSource[pid] = 角色`；
2. 广播 `S_PICK_CHARACTER { PlayerId = 0, CharacterId = 该角色 }`，
   把所有**同技能**的角色变灰（含数据表里同技能的其它角色，例如技能 0 的 Madeline/Liliana；
   Madeline 不在选人列表里，广播无害）；
3. 广播 `S_PICK_CHARACTER { PlayerId = 自己, CharacterId = 自己的模型 }`：
   恢复所有人看到的头像、把自己的 `_submit` 锁回 `true`；
4. 如果自己模型的技能此刻空闲，再广播
   `S_CANCEL_PICK_CHARACTER { PlayerId = 0, CharacterId = 自己的模型 }`
   把模型角色重新点亮（`PlayerId=0` 不会复位任何人的提交状态，也不会动头像）。

最终界面状态：选中的技能角色灰；自己模型的技能若已空出则重新亮；自己的头像恢复；
其他人仍然可以选自己模型空出来的技能。

### 完成 / 超时

- `MaybeComplete`：所有**参与者**（`!IsDummy && !IsSpectator`）都有 `SkillSource` 时，
  先标记 `_completed = true`，再给非参与者补技能，最后 `SetStopWatch(40)` 进入原版 5 秒倒计时。
- 到 40 秒仍未选的参与者：`AssignTimeoutSkills` 从剩余技能随机；非参与者一并补。
- 非参与者（旁观者 / 假人）不阻塞阶段；在完成或超时时分配一个剩余技能。
  这只是服务端真值，不影响玩家可选技能（分配发生在所有参与者都完成之后）。

## 2.3 为什么不是“只点亮自己的模型”

早前的草案是“技能阶段只点亮自己的模型，别人的模型保持灰”。那样确实会**禁止选择别人模型的技能**，
与“所有技能重新可竞争、先到先得”冲突。最终改为：

- 技能阶段的灰 = **该技能当前被占用**，不是“该角色被选成模型”；
- 进入技能阶段时所有人的默认技能都被释放，所有模型角色都重新点亮；
- 谁先选，谁占用；被占用后同技能角色全部变灰，包括原模型主人也不能再拿它“保持默认”；
- 自己选自己模型 = 保留默认；被别人先选走 = 只能改选 / 随机。

## 2.4 配置

段 `[CluePickSkill]`：

| 键 | 默认 | 范围 | 含义 |
| --- | --- | --- | --- |
| `AllowRandom` | true | — | 技能阶段是否允许“随机”按钮 |
| `SkillPickSeconds` | 20 | 5–40 | 技能阶段独立倒计时（进入阶段时读取） |

旧版的 `Anonymous` 已删除：技能阶段**始终匿名**，不再提供关闭匿名的配置。

## 2.5 中途加入 / 旁观者 / 假人

原版在非 `Lobby` 阶段加入的人会被标成**旁观者**（`EnterPlayer`，:175243），
不参与本局玩法。因此不需要“禁止中途加人”的特殊逻辑；我们保留一层轻量防御，不依赖
“选人阶段不会有人加入”这个前提：

- **模型阶段加入**：原版处理；`EnsureModelsRecorded` 在进入技能阶段时补记模型。
  如果加入的是旁观者且一直没选，`AllModelsConcrete` 会等原版 40 秒强制分配再进技能阶段
  （最多多等原版那 40 秒，不会卡死）。
- **技能阶段加入**：`EnterPlayer` 的 Postfix（仅在 `Stage.Skill` 生效）
  1. 撤销它的默认技能（模型阶段可能刚分配过）；
  2. 把 pid / 模型加进 `_pickPlayers` / `_pickCharacters`，防止原版 40 秒强制分配再给它
     一个默认技能（可能和已选技能重复）；
  3. 非参与者：全局回显模型并锁定界面，阶段末补技能；
  4. 参与者（理论上级少见的非旁观者）：不锁定，允许它参与选择；`MaybeComplete` 会等它，
     超时随机兜底。
- **收尾窗口（已 `_completed`）加入**：`EnterPlayer` 直接补技能（参与者随机；
  非参与者走 `AssignNonParticipants`），避免带着空技能进 `GameStart`。
- **离场**：如果离场者在技能阶段已经选了技能，`BroadcastSkillFree` 把该技能对应角色
  **全局重新点亮**，还在选的人可以再选；随后 `MaybeComplete` 检查剩余参与者。

**结论**：不主动踢人、不伪造“只有某个客户端看得到”的状态；只做全局的撤销/锁定/补技能。
如果以后要做“选人阶段拒绝加入”，那是房主加入策略，应该单独做一个功能，不要混进本功能。

## 2.6 RuleBreaker

`SkillComponent.UseRuleBreaker`（:180672）原版按目标的 `Player.CharacterId`（模型）
取 `CharacterData.Skill`。技能与模型解耦后，这会把“目标的实际技能”复制错。

补丁只在这种情况接管：目标的 `SkillComponent.Data` 与模型默认技能**不同**。
接管时复刻原版顺序：

1. `BroadcastWorldSFX(BlackholeSfx)`；
2. 按目标**实际技能**找一个 `CharacterData`，`AllocateSkill`；
3. 实际技能是 `Catastrophe` 时广播 `S_NOTIFY_LUNA_ABILITY`；
4. `Data.IsActive` 时 `Owner.CanUseSkill = true`；
5. `SendVFX(ShadowPartnetVfx, targetId)`；
6. 跳过原版。

如果实际技能与模型默认相同，直接放行原版，行为完全一致。

## 2.7 已知限制 / 观感

- 进入技能阶段后，客户端 HUD 上的技能图标可能还显示模型默认技能，直到本人选定 / 超时
  分配后收到 `ChangeSkill`。选人阶段没有战斗，不影响玩法。
- “完全重置”会清空所有玩家头像；头像在每个人选完技能时恢复，未选的人在超时分配时恢复。
  这是为了全局同步和“没有只对单个客户端成立的状态”而接受的观感代价。
- 模型阶段的 `S_TIME{0}` 被拦下后，客户端按钮不会隐藏；如果 `StartSkillPhase` 异常，
  会退回原版：下一拍 `S_TIME{-1}` 仍会让客户端隐藏按钮并按 45 秒进游戏，同时
  `RestoreUnassigned` 保证不会带着空技能进 `GameStart`。
- 热开 / 热关都做了收尾；但**不建议在技能阶段中途热开**（`EnsurePhase` 会把它当成模型阶段
  重新接管）。要改开关请在选人开始前或局内非选人阶段操作。

## 2.9 实测清单（需要房主 + 至少两个客户端）

1. 全员选完模型（含随机）→ 立即进入技能阶段：所有人头像清空、所有模型重新点亮、
   提交状态复位、倒计时 = `SkillPickSeconds`。
2. 选自己模型 → 保留默认技能；该技能对应的角色变灰；别人不能再选。
3. 选别人模型的技能（在它还没被选走时）→ 成功；原模型主人若还没选，自己模型已灰，
   再提交只能随机。
4. 两人抢同一技能：先提交者成功，后提交者收到随机兜底（或界面已点不到）。
5. 技能阶段按随机 / 不选到超时：从剩余技能随机；不存在空技能（除非技能数少于参与者）。
6. 匿名性：其他人只看到角色变灰，不知道是谁选的。
7. 假人 / 旁观者不阻塞；阶段末有技能；中途加入不产生重复技能。
8. 技能阶段关闭开关：所有人要么保留已选技能，要么恢复模型默认 / 空闲技能；
   界面锁回“已提交模型”，按原版收尾。
9. RuleBreaker 复制目标实际技能（造一个“模型与技能不同”的 target 验证）。
10. ①：任务满无尸体 → 白胜；有尸体且剩余 ≥ `ThresholdSeconds` → 5 秒延迟 + 倒计时冻结；
    剩余 < 阈值 → 立即报告；延迟中手动报告 → 不进延迟补发；延迟中热关 → 立即补原版。
