# 线索伪造（`Features/Host/ClueFake/`，纯服务端）

> **一句话**：黑方 / 黑幕在**发信机的聊天频道**里用 `/f` 录入一条虚假线索（时间 / 人物 / 房间 / 活动），
> 写进目标房间设备的 `ClueList`（扫描才可见）；执行时会在**那台发信机**留下原版的
> 「XX 发送了消息」线索作为代价；会议播报与 `/clue` 末尾提示「有 N 条可能为伪造」。

游戏版本基准：**0.1.18**。本文只描述**代码实际行为**，`0.1.18 :N` 是反编译
（`.tmps\decomp\Assembly-CSharp-0.1.18.decompiled.cs`）行号。

---

## 1. 口径（用户定案）

1. **归属**：黑方（`EPlayerColor.Black`）或黑幕（`EPlayerColor.Dark` / `MasterMind`）。
2. **阶段**：`EGameState.Survive`（生存阶段）。
3. **入口**：只能在**发信机（聊天设备）的聊天频道**里输入 —— 与发信机留言共用一条通道，
   不是平板普通聊天。
4. **人物 `b` / `m`**：不是角色线索 id，而是**本局实际黑方 / 黑幕玩家的便捷输入**
   （解析成真实 `PlayerId`）。
5. **次数**：`MaxPerRound`，`QuotaMode = player`（每人）或 `team`（黑 / 黑幕各一个池）。
6. **黑方开关**：`BlackEnabled`（默认 true，热读）——关闭后只有**黑方（Black）**不能用，黑幕（Dark / Mastermind）不受影响。
   回大厅清零。
6. **代价**：伪装成功后，发信机按原版语义留一条「发送了消息」线索。
7. **提示**：只报数量、不标是哪一条。

## 2. 入口与前置条件

`ChatCommandHook`（挂 `HostPacketHandler.Handle_C_CHAT_MESSAGE`，0.1.18 :177661）原先只认
`NormalChat`；现在**额外认领 `SecretChat`（黑方秘密终端）里的 `/f`**（以及进行中会话的下一条输入），
其余发信机留言与其它模块的命令一律放行。

判据（与 `RelayDeviceChat` :177827 同一组）：

| 条件 | 依据 |
| --- | --- |
| `room.State == Survive` | 原版 :177829 |
| `player.IsAlive` | 原版 :177829 |
| `ChatDevice.IsOccupiedBy(player)`（:165163） | 原版 :177834 |
| 黑方 / 黑幕 | 本功能的产品口径（原版没有限制） |

普通聊天（`NormalChat`）里输入 `/f` 会收到一句「必须在发信机上执行」，不会广播。

## 3. 参数与交互

```
/f [时间] [人物] [房间] [活动]
```

| 参数 | 接受 | 说明 |
| --- | --- | --- |
| 时间 | `07:00am/pm`、`21:49`（24 小时制）、`469`（分钟）、`+25` / `-15`（偏移分钟） | 单位 = 游戏内分钟，7:00am = 420（`:27277`）；允许 `[420, 23:59]`（可以写到「现在」之后） |
| 人物 | 昵称 / `#id` / `b` / `m` | `b` = 本局黑，`m` = 本局黑幕 |
| 房间 | `RoomDic` 编号 / 房间名 | 房间名走 `ERoomType` 词条 |
| 活动 | 该房间候选的编号 / 名称 | 候选来自**真实设备**（`DeviceManager.Objects`，按 `RoomID` 分组、`WhatType != WNone/WFusebox`） |
| `r` | 房间位 / 活动位 | 在当前候选里随机 |
| `x` | 任意位 | 该字段**保留真实值**（进入改写模式，等下一条真实线索）。`/f x x x` = 原样保留只标记伪造；`/f x m x` = 只把身份改成黑幕玩家 |
| `-` | 任意位 | 占位符：这一项暂时不提供，留到交互式补全；其它已给的项照常生效 |`n| `h` / `help` | 单独一个参数 | 打印本命令自身的帮助 |

参数不完整时进入**交互式补全**：登记一份 per-player 会话，玩家在发信机里的下一条输入就是答案；
**从第一个还没填的项开始问**（不是固定从时间开始）。例如：

```text
/f 09:24pm - 广播室
  → 时间、房间已给；只问身份（跳过房间）
```

**任何一项非法（格式不对 / 编号不存在）都视为 `-`**，继续解析后面的项，最后进入交互式补全该项，而不是整条命令失败。`n`n`exit` 取消；闲置 120 秒 / 离开 `Survive` / 回大厅 / 玩家死亡都会清掉。

回执格式：

```text
虚假线索[7:49am，LCK于广播室留下了消息]已录入。剩余可录入次数 0/1。
```

⚠️ **回执走密聊频道**（`S_CHAT_MESSAGE.Type = SecretChat`，只单发给操作者）：
玩家是在发信机 UI 里输入的，普通聊天（`NormalChat`）的回执在那个界面里看不到。
非发信机入口（平板聊天里的 `/f`）才退回普通聊天，只回一句「必须在发信机上执行」。

## 4. 写入路径（伪证）

```
目标房间 + 活动
  → FindDevice(roomId, whatType)            // 该房间第一台匹配的真实设备
  → new PropositionInfo { PlayerId, Time, RoomId }
  → UnknownFields.SetWhat(info, (int)what)  // 字段 100，必须早于 Clone
  → device.ClueList.Add(info)               // 服务端真值
  → room.Broadcast(S_ADD_CLUE{DeviceId, Info = info.Clone()})
```

- **为什么写设备**：`S_ADD_CLUE` 在客户端只喂 `ClueMirror`（:43621），玩家平板/`/clue` 的来源是
  **扫描**（`Device.Scan` :166315 → `S_SCAN_DEVICE` → `TakeDeviceClue` :27588）。
  写进 `ClueList` 才能被"搜到"。
- **未装本模块的端**：字段 100 被原样忽略；0.1.18 的普通线索模板已删 `{what}`，
  所以它看到的是原版句式（没有活动段），wire 安全。
- **去重**：同设备同键（`PlayerId + Time + RoomId`）已存在时拒绝，与客户端
  `AlreadyExistClue`（:27607）同口径。
- **可调查**：调查阶段由原版 `StartDetective`（`ClueList.Count > 0 ⇒ Bubble = -1`）统一处理，
  本功能不额外设置。

## 5. 发信机痕迹（代价）

伪装成功后写一条**匿名的角色线索**（不写真实玩家 id）：

| 操作者 | `PlayerId` | 渲染 |
| --- | --- | --- |
| 黑（`EPlayerColor.Black`） | `66613`（`Define.BLACK_DESTROY_ID`） | 「黑」 |
| 黑幕（`EPlayerColor.Dark`） | `11037`（`Define.MASTERMIND_SABOTAGE_ID`） | 「黑幕」 |

同时写未知字段 **100 = `WChat`**，并自行做原版同口径的 **30 秒合并**（同角色 + 同设备 + 同桶
→ `S_REMOVE_CLUE` 旧副本 + `S_ADD_CLUE` 新副本），最后给操作者发 `S_LEFT_CLUE{RoleFace=true}`。

渲染特例（否则会显示成原版角色文案）：

- 客户端 `Core/ClueWhat.cs` 的 `TryResolve`：角色线索 + 字段 100 == `WChat` ⇒ 放行，
  `{what}` 段显示「留下了消息」；
- 服务端 `/clue` 的 `ClueIndex.ActOf` 同一特例；`IsDestroyRow` 对它返回 false
  （66613 本身属于「销毁证据」判据，不特判会走"设备名处"格式）。

⚠️ **痕迹是"真的"**：谁在调查阶段扫这台发信机，谁就看见「黑/黑幕 留下了消息」；
伪装线索本身则写进**目标房间**的设备，两者是不同的对象。
⚠️ 未装本模块的客户端不认字段 100，它看到的是原版角色文案（「销毁了证据 / 切断了电力」），
但「黑/黑幕」这个身份仍然正确——匿名性不依赖本模块。

## 6. `x` 重写

`/f <时间> <人物> x` 不写伪证，而是登记一个**一次性槽**（`ClueFakeState.RewriteSlot`），
到期时间 `RewriteTimeoutSeconds`（默认 300 秒）。

应用点：`GameRoom.Broadcast(IMessage, int)` 的 Prefix（`ClueFake/Patch.cs` 的 `RewriteHook`，
`[HarmonyPriority(Priority.Low)]`）：

1. 命中 `S_ADD_CLUE` 时，把包内 `Info` 的 `Time` / `PlayerId` 换成槽值；
2. 用旧键在服务端 `ClueList` 里找到同一个对象，改它的 `Time` / `PlayerId`；
3. 补字段 100（改键后 `RecordDetail.StampWhat` 按旧键查不到旁路表）；
4. 消耗槽。

**为什么不挂 `RecordLastUsingPlayer`**：该方法自 2026-10-20 起被 `ClueMerge` **接管**
（Prefix 返回 false，项目内约定 Postfix 不跑），而 `ClueMerge` 也可能被关掉；
两条分支最后都会走 `Broadcast`，所以那里是唯一稳定收口。

**边界**：

- 角色线索（11037/11038/66613）**不参与**重写（保留槽，等下一条普通线索）；
- 本功能自己刚写的伪证**不参与**重写（先登记伪证键再广播，见 `TryWriteFake`）；
- 只作用于**下一条**广播的 `S_ADD_CLUE`，命中即清槽；过期只记日志；
- ⚠️ 这是本模块**第二处**主动改写 `Time` / `PlayerId` 的地方（第一处是 `ShadowSabotage`
  的时间 / 身份污染）。边界与备案见 `AGENTS.md` §4.1。

## 7. 「可能为伪造」提示

- `ClueFakeState` 记录本局伪证键（`玩家:时间:房间`）；
- `ClueIndex.ClueRow` 增加 `Fake` 标记，扫描登记 / 设备真值收集时置位；
- 会议播报（`Report.SendReport`）在末尾追加：

```text
（在当前所搜集到的全部线索中，有 1 条线索可能为伪造）
```

统计口径是**该玩家搜集到的全部线索**（不是报告窗口内）。

**只在会议开始的一次性播报里提示**（配置 `ReportHint`，独立气泡，不跟正文挤在一起）；`/clue` 不再追加任何伪造提示
——否则每次筛选都弹一次、N 还随条件变化，既重复又没法据此定位（2026-11-10 用户口径）。

**行标**：`/clue` 逐条列出时，只有**黑方 / 黑幕 / 死者**会把伪造的那一行标成
`[伪造] 07:49am · 广播室 · …`（`CanMarkFake`）；白方活人看不到行标，只能靠开局那次数量提示。

| 键 | 默认 | 说明 |
| --- | --- | --- |
| （段开关） | 开 | 功能总开关 |

| `SearchHint` | true | `/clue` 末尾提示 |
| `RewriteTimeoutSeconds` | 300 | `x` 槽有效期 |

| 限制 | 说明 |

| 只能发信机内用 | 由用户口径决定；平板普通聊天只给提示 |

## 11. 实机验证清单

1. 启动日志：`启用 N，失败 0`，且 `ClueFake` 的补丁数 > 0。
2. 黑方在发信机上输入 `/f` → 依次收到「时间 → 身份 → 房间 → 活动」提示；
   `exit` 能取消。
3. 完整参数 `/f 7:49am b 广播室 1` → 回执「…已录入。剩余可录入次数 0/1」。
4. 同一发信机上出现一条「黑/黑幕 留下了消息」线索（调查阶段扫描可见；未装端显示角色文案但身份仍是黑/黑幕）。
5. 目标房间的设备被扫描 → 能看到伪证（装本模块的客户端有活动段）。
6. 会议开局播报之后出现一条**独立气泡**「【伪造提示】你所搜集到的全部线索中，有 N 条可能为伪造」；`/clue` 不再提示。
7. `/f 8:15am 3 x` 后，下一次真实设备使用产生的线索被改成 8:15am / #3；
   日志出现「x 重写了一条线索」；改写后的那条线索在 `/clue` 里同样带 `[伪造]`（黑/黑幕/死者可见）。
8. 白方输入 `/f` → **不认领**（如同本模块没注册；秘密终端里原版会静默丢弃）；死者/非黑队执行 → 被拒绝；平板聊天/公开发信机输入 `/f` → 提示去黑方秘密终端。
