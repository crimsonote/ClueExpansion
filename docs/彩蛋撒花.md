# 彩蛋：尸体撒花（FlowerCarpet）

纯服务端彩蛋。白方任务完成度达到阈值，或进入调查阶段时，
在**每一具尸体所在房间的地板上**按**固定密度**撒花（可拾取物品）。

代码：`Features/Host/FlowerCarpet/`（`Feature.cs` 配置 + `Logic.cs` 执行 + `Patch.cs` 两个挂点）。

---

## 1. 触发与去重

| 触发 | 挂点 | 条件 |
| --- | --- | --- |
| 进入调查阶段 | `Server.Game.GameRoom.ChangeGameState` 的 Postfix | `state == Detective` 且 `TriggerOnDetective` |
| 任务完成度 | `GameRoom.SurvivalTick` 的 Postfix | `CurrentPoint / GoalPoint >= MissionThreshold` 且 `TriggerOnMission` |

- 每局只撒一次（`_scattered`），回到 `Survive` / `Lobby` 时复位。
- **还没有尸体时不置标记**：等有了尸体再撒（否则开局那一秒就消耗掉这次机会）。
- `MissionManager` 是 internal 类（0.1.18 :169148），进度只能反射读。

## 2. 判定链（四层，缺一不可）

| # | 判据 | 依据 |
| --- | --- | --- |
| ① | `AreaManager.ValidPosition(p)` | 0.1.18 :176524，读 `Managers.Data.MapArray`，格子 **224**，**0 = 不可通行** |
| ② | `GetArea(p).Data.DataId == 房间` | 0.1.18 :176473，只撒在尸体所在房间 |
| ③ | `Blocked(x, y)` | 设备 + 地图本体的非 trigger `Collider2D.bounds` |
| ④ | `TooClose(...)` | 与已撒下的花相距 `MinGap`（装饰密度，**不是**避障手段） |

拿不到房间时（`GetArea(center) == null`）直接跳过并 Warn。

### 2.1 朵数怎么算（2026-10-21 改为固定密度）

用户口径：**要固定密度，不是固定总量** —— 半径调大时朵数要跟着涨，小房间也不该挤成一团。

```text
want = min(采样圆面积, 尸体所在房间面积) × Density / 10000
want = clamp(want, 1, MaxFlowers)
```

- 房间面积 = `MapArray` 里属于该房间类型的格数 × 224²（`Area` 本身不带格数，只能数网格）；
- 取 `min` 的理由：小房间按房间算，不会被撒到墙外；大房间按采样圆算，不会白采；
- `Density` 默认 **0.8/万平方单位** ⇒ 半径 400 的圆里约 **40 朵**（与旧默认等价）；
- `MaxFlowers` 默认 **400**，防止半径调大后一次撒出上千朵。

`MinGap` 仍然只负责"花与花之间别叠"，不参与朵数计算。

## 3. 两个坑（都实际踩过）

### 3.1 `Corpse.RoomID` 恒为 0 —— 「撒了 0 朵花」的真凶

2026-10-20 实测：日志只有 `彩蛋：在 1 具尸体所在房间的地板上撒了 0 朵花。`，
没有异常、没有 Warn，两轮采样全空，看着像"位置判定太严"。

实际原因在参数上：

- `Device.RoomID` 是 `private set`（0.1.18 :166241）；
- 全类唯一写入口是 `Device.SetInfo(Data.DeviceData)`（:166333，
  `RoomID = GetArea(DeviceData.Pos).Data.DataId`）；
- **`Corpse` 从不调用它** —— 构造函数（:171851 / :171890）只填 `DeviceInfo`，
  `DeviceManager.SpawnDevice`（:166688）只做 `DeviceInfos.Add` + 广播；
- ⇒ `corpse.RoomID == 0`，而 `area.Data.DataId` 是 **1000xx** ⇒ ② 永远不等。

修法：**房间 id 由采样中心自己解析**，不要读 `corpse.RoomID`。

> 顺带：`corpse.DeadPos` 是死亡瞬间的玩家位置，`corpse.DeviceInfo.Pos`
> 在此基础上 `X += ±100`（朝向偏移，:171866）。两者通常同房间，但取房间一律以 `DeadPos` 为准。

### 3.2 `CompositeCollider2D.bounds` 是整间房的 AABB

客户端 `MapManager.GetParent(id)`（0.1.18 :30549）给每个房间建一个 `@<roomId>` 根节点，
挂 `Grid`（224×224）、静态 `Rigidbody2D`、`CompositeCollider2D`（:30554），
把该房间所有子碰撞盒**合批**。

- 收集墙体 / 家具时**只收 `BoxCollider2D`**，绝不能把 `CompositeCollider2D` 当障碍 ——
  它的 `bounds` 覆盖整间房，会把整间房判死（一朵都撒不出）。
- 子 `BoxCollider2D` 的几何独立于合批，仍在原来的世界位置，可以直接读 `bounds`。

## 4. 为什么读 `bounds` 而不是物理查询

- **不能**用 `Physics2D.OverlapPoint(..., LayerMask.GetMask("Block"))`：
  AOI 剔除是靠**改 `gameObject.layer`** 实现的（0.1.18 :31466 把物体挪到 19 层），
  远处房间的家具会被挪出 `Block` 层 ⇒ 查不到 ⇒ 花穿模。
- `Collider2D.bounds` 是世界坐标 AABB，不受层、不受 `enabled` 影响。
- `GetComponentsInChildren(..., includeInactive: true)` 必须带上：被剔除的物体可能整块
  `SetActive(false)`。
- 代价：AABB 是包围盒，斜放的家具会被略微放大。撒花是装饰，可接受。

## 6. 失败时的诊断

只有在某个尸体**一朵都没撒下**时，才打一条分层明细（正常局不刷屏）：

```text
彩蛋：房间 100012 的尸体 (6608,4700) 一朵都没撒下 ——
严格轮 1600 次采样（网格拒 12 / 房间拒 1330 / 碰撞拒 210 / 间距拒 0 / 建物失败 0）；
降级轮 1600 次采样（房间拒 1330 / 碰撞拒 210 / 间距拒 0 / 建物失败 0）。
```

拿着这条就知道卡在哪一层，不必再进游戏试。
